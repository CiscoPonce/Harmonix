# Phase 12.5: Spotify Connect UX — Context

**Gathered:** 2026-07-20  
**Status:** Ready for planning  
**Depends on:** Phase 12 (OAuth backend, Settings card, Library consumer) — code complete pending 12-11 human gates

<domain>
## Phase Boundary

Make Spotify linking feel like modern one-click OAuth for **end users**. Learners should connect without visiting Settings first, without leaving Harmonix on a full-page redirect when avoidable, and without ever seeing Developer Dashboard steps.

**In scope**

- Popup (or equivalent in-tab) OAuth 2.0 Authorization Code + PKCE on web — Harmonix stays visible; Spotify login/consent in a focused window
- **Connect Spotify** primary action in Library when disconnected (empty Spotify shelf + recovery states)
- Optional first-run / onboarding prompt after signup (“Connect Spotify to see your playlists?”)
- Minimal callback page that notifies the opener (`postMessage`) and closes — server token exchange unchanged
- Android: preserve Settings entry; evaluate Custom Tabs / in-app browser parity where App Links already apply
- Operator runbook section: one-time Client ID + redirect URI + allowlist (invisible to learners)

**Out of scope**

- Replacing Spotify Developer app registration (required for any integration)
- Extended Quota / public-release entitlement (remains 12-11 gate)
- Changing scopes, matching, export, or token crypto from Phase 12
- Primary Connect button **only** in Library (Settings card remains for manage / disconnect / reconnect)

</domain>

<decisions>
## Implementation Decisions (locked for planning)

### End-user experience
- **D-12.5-01:** Web default connect path uses **popup OAuth** when `window.open` is available; fall back to full redirect (current behavior) when popups are blocked or on mobile web.
- **D-12.5-02:** Library shows an inline **Connect Spotify** button when status is disconnected — not only “Open Settings”.
- **D-12.5-03:** Settings Spotify card remains the place for Connected / Reconnect / Disconnect; Library connect reuses the same `POST /api/spotify/auth/start` + validated `accounts.spotify.com` URL.
- **D-12.5-04:** Success still lands on Library with Spotify group visible (`/playlists?spotify=connected` or equivalent refresh signal); errors recover on Settings with allowlisted reasons (unchanged security model).
- **D-12.5-05:** Popup callback page must not expose tokens, codes, or raw OAuth `state` to the client — only allowlisted outcomes (`connected` | `error`).

### Technical constraints (carry forward from Phase 12)
- **D-12.5-06:** PKCE, SHA-256 OAuth state, encrypted token storage, and fixed env return URLs stay server-owned.
- **D-12.5-07:** Spotify failures must not clear Harmonix Library content.
- **D-12.5-08:** Provider tokens never enter client storage, query strings, analytics, or logs.

### Operator setup (document only — not shown in app UI)
- **D-12.5-09:** Document one-time operator checklist in runbook: Dashboard Client ID, exact redirect URI, Development Mode allowlist (≤5 users), VPS `SPOTIFY_CLIENT_ID`, restart.

</decisions>
