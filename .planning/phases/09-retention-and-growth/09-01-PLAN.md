# Phase 9: Retention, Gamification, and Personalization

## Overview
This phase focuses on shifting Harmonix from a stateless utility into a sticky, engaging daily habit. By introducing user-defined playlists, a gamified progression system, spaced repetition, and multi-language support, we will drastically increase Day-7 retention and overall user ownership of the platform.

## 1. Localization / Language Selection Flow
**Goal:** Allow users to explicitly define their learning parameters to support multi-language scaling.

* **Onboarding Screen:** A new `/onboarding` route (or modal) for new and existing users who haven't set their preferences yet.
* **Database Updates:** Update the `users` table to include `native_language` (e.g., "en") and `target_language` (e.g., "es").
* **AI Context Updates:** Modify the NVIDIA NIM extraction prompt to dynamically use the user's `native_language` for translations and `target_language` to identify the song's language.
* **UI Indicator:** Add a language toggle or badge in the settings/dashboard reflecting their current learning path.

## 2. User Playlists & Collections
**Goal:** Give users ownership over their learning path by allowing them to curate custom collections of songs and vocabulary.

* **Database Architecture:**
  * `playlists` table: `id`, `user_id`, `name`, `description`, `created_at`.
  * `playlist_songs` table: `playlist_id`, `song_id`, `added_at`.
* **UI Integration:** 
  * Add a "Save to Playlist" button on the Player page.
  * Create a `/playlists` page in the dashboard where users can view and manage their collections (e.g., "Spanish Gym Playlist").
* **API Endpoints:** Create `GET /playlists`, `POST /playlists`, and `POST /playlists/:id/songs` routes.

## 3. Gamification Expansion (Badges & Milestones)
**Goal:** Enhance the existing streak and XP system by awarding tangible, unlockable milestones to drive engagement.

* **Database Architecture:**
  * `badges` table (static/system level): `id`, `name`, `description`, `icon`, `criteria_type`, `criteria_value`.
  * `user_badges` table: `user_id`, `badge_id`, `unlocked_at`.
* **Milestone Definitions:** Define a core set of 5-10 badges (e.g., "7-Day Streak", "Learned 50 verbs", "Pop Music Master", "First Playlist Created").
* **Unlock Logic:** Implement a background check or middleware after learning sessions to evaluate if a user crossed a badge threshold, triggering an unlock.
* **UI Integration:** Add a "Trophy Room" or "Achievements" section to the Dashboard to display locked and unlocked badges.

## 4. Spaced Repetition "Review Room"
**Goal:** Provide a dedicated practice mode where users review their saved/learned words using the flashcard method for long-term retention.

* **Database Architecture:** 
  * Extend the existing `progress` or `user_words` tracking to include spaced repetition fields (e.g., `next_review_date`, `ease_factor`, `interval`).
* **Review Algorithm:** Implement a basic SM-2 algorithm (or similar) to calculate when a word should be reviewed again based on user feedback (Hard, Good, Easy).
* **UI Integration:** 
  * Create a `/review` route. 
  * Flashcard UI: Show the word in the context of the lyric snippet, ask for the translation, and then reveal the answer with feedback buttons.
  * Dashboard Hook: Add a notification or metric showing "X words to review today".

## Execution Strategy
1. **Database Migrations:** Add tables for Playlists, Badges, and Language Preferences.
2. **Backend API:** Build out the CRUD operations for the new features.
3. **Frontend Views:** Implement Onboarding, Playlists, and Review Room UI.
4. **Integration:** Wire up the AI prompts to respect the language selections and the flashcards to the SRS algorithm.
