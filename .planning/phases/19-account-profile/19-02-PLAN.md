### Step 2: Web header

In the existing Profile section, top of the settings column:

- Circle, 56px, shows the photo when `user.has_avatar` is true. Load it with `apiFetch('/user/avatar')` and an object URL, revoked on change/unmount. While there is no photo, keep the letter circle. Letter is the first character of `username`, otherwise of `email`.
- A file input `accept="image/jpeg,image/png,image/webp"` labeled with `profile_photo`. On pick, `PUT /api/user/avatar` with the file as a `Blob` (not a string) and `Content-Type` set to that file’s type, then `refreshUser()`. `apiFetch` turns a string body into `application/json` when the header is missing, which would reject the photo. Non-OK shows the JSON `error` string under the card. Do not send the password.
- `profile_remove_photo` calls `DELETE /api/user/avatar` and refreshes. Hidden when `has_avatar` is not true.
- The large name is `user.username` when set, otherwise `profile_username_hint`. Under it, the bio when set, otherwise `profile_bio_hint` in the muted color. Under that, the email in the muted small style so the learner can see which login this is.
- To the right of the name, the streak from `GET /api/progress/stats` field `streak_days` (default 0). Format with `tp('streak_days', n)`. Fetch once when `user` is set. A failed stats call shows `0`, not an error banner.
- Editing: username and bio inputs on the card, maxlength 20 and 160, Save calls `PATCH /api/user/profile` with `{ username, bio }`. Map `username_taken` and `username_invalid` to the new strings when `code` matches; otherwise show `error`. Then `refreshUser()`.
- Keep the language chips that already sit in this card, under the bio.
- Do not move the password card or the languages card above this header.

**Verify**: `cd client && npx tsc --noEmit` → exit 0.

If a web dev server is already running, open Settings in the browser and confirm the header is the first card, Save rejects a 2-letter username without wiping the email display, and the streak number renders. If no server is running, say so in the handoff. Do not start a production deploy.

### Step 3: Android header

Add `image_picker` to `mobile/pubspec.yaml` dependencies. Do not change the `version:` line.

`mobile/android/app/src/main/AndroidManifest.xml` currently has `xmlns:android` only. Add `xmlns:tools="http://schemas.android.com/tools"` on the manifest tag, then:

```xml
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" tools:node="remove"/>
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES" tools:node="remove"/>
<uses-permission android:name="android.permission.READ_MEDIA_VIDEO" tools:node="remove"/>
```

Pick with `ImagePicker().pickImage(source: ImageSource.gallery, maxWidth: 1024, maxHeight: 1024, imageQuality: 85)`. That uses the system photo picker. Do not request a runtime storage permission in Dart.

Replace the email `ListTile` at the top of the list with a card (same surface, border, and radius as the languages container):

- Circle avatar, photo bytes from `GET /user/avatar` when `user['has_avatar'] == true`, otherwise the initial or the person icon.
- Username, or `profile_username_hint`.
- Bio, or `profile_bio_hint`.
- Email underneath, muted.
- Streak using the `_stats['streak_days']` value already loaded, label `context.tr('streak')`, the number large.
- Tap the text block to edit username and bio (dialog with two fields and Save is enough). Save calls a new `ApiClient.patchProfile` → `PATCH /user/profile`, then `auth.refreshUser()`.
- Tap the avatar to pick, then `PUT /user/avatar`. Remove photo calls `DELETE /user/avatar`.

Leave the stats row and the achievements list as they are. Plan 19-03 moves those counts and makes the achievements match them. The header streak is the only streak this plan adds.

Add `patchProfile` and `deleteAvatar` through the existing `request()` method (`PATCH` and `DELETE` already exist). `request()` JSON-encodes its body, has no `PUT`, and rejects a non-JSON response. `putAvatar` and `getAvatarBytes` must call the same HTTP client with the same `Authorization` header and must not go through `request()`. `getAvatarBytes` returns the raw body bytes.

**Verify**: `cd mobile && flutter analyze --fatal-infos lib/screens/settings_screen.dart lib/services/api_client.dart lib/state/auth_state.dart` → no issues.

`grep -n "READ_MEDIA_IMAGES\|READ_EXTERNAL_STORAGE" mobile/android/app/src/main/AndroidManifest.xml` shows only the `tools:node="remove"` lines.
