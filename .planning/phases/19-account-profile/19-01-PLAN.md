### Step 2: Profile service

Create `server/services/profileService.js`. Export:

- `RESERVED` = `['admin','harmonix','support','hello']`
- `normalizeUsername(value)` — trim, lowercase. `''` or `null` means clear (return `null`). Otherwise require `^[a-z0-9_]{3,20}$` and not reserved. Throw a typed error the route maps to 400 `{ error: 'Use 3–20 letters, numbers, or underscores.', code: 'username_invalid' }`.
- `normalizeBio(value)` — trim. `''` or `null` means clear. Reject if length > 160 or if the string contains a character code below 32, or `<`, or `>`. Error code `bio_invalid`, message `Bio must be 160 characters or fewer, with no markup.`
- `saveProfile(userId, { username, bio })` — update only the fields that were sent. Unique violation on `idx_users_username` becomes code `username_taken`.
- `readProfile(userId)` — `{ username, bio, has_avatar }`. Missing user returns `null`. `has_avatar` is true only when `user_avatars` has a row.
- `saveAvatar(userId, buffer, mime)` and `readAvatar(userId)` and `deleteAvatar(userId)`.
- `sniffImage(buffer)` — return `'image/jpeg'`, `'image/png'`, or `'image/webp'`, or `null`.
  - JPEG: bytes `FF D8 FF`, then `jpeg.decode(buffer, { useTArray: true })` succeeds. A thrown decode is `null`.
  - PNG: bytes `89 50 4E 47 0D 0A 1A 0A` and the buffer includes the ASCII `IEND`.
  - WebP: bytes `RIFF` at 0, `WEBP` at 8, and `buffer.length >= 12`.
  - Ignore the client’s `Content-Type` when it disagrees with the bytes. Store the sniffed mime.

Do not log the image bytes or the username of a failed attempt beyond the status code.

**Verify**: `cd server && JWT_SECRET=test JWT_REFRESH_SECRET=test NODE_ENV=test npx mocha services/profileService.test.js --timeout 20000` → exit 0, covering: valid username lowercased; `Ab` rejected; `admin` rejected; bio of 161 rejected; bio with `<` rejected; empty string clears; second user cannot take the same username; a 1×1 JPEG from `jpeg-js` `encode` is accepted; a buffer starting with `<html` is rejected; PNG and WebP magic headers of the right shape are accepted; a truncated JPEG (`FF D8 FF` plus garbage) is rejected.

### Step 3: HTTP routes

Create `server/routes/profile.js` and mount it in `server/index.js` on the same stack as the other user routes:

`app.use('/api/user', authenticateToken, profileRouter)`

Routes, all requiring `req.user.id`:

- `PATCH /profile` with JSON `{ username?, bio? }`. At least one of those keys must be present, otherwise 400 `{ error: 'Nothing to update.', code: 'empty_profile' }`. Unknown keys are ignored. Success `200` with `readProfile`. Taken username is `409` `{ error: 'That username is taken.', code: 'username_taken' }`. Invalid values use the messages from step 2.
- `PUT /avatar` with `express.raw({ type: ['image/jpeg','image/png','image/webp','application/octet-stream'], limit: '512kb' })` on this route only. Sniff the body. Bad image is `400` `{ error: 'Use a JPEG, PNG, or WebP image under 512 KB.', code: 'avatar_invalid' }`. Success `204`. A body over the limit is Express `413`.
- `GET /avatar` returns the stored bytes, `Content-Type` set to the stored mime, `Cache-Control: private, max-age=3600`, `X-Content-Type-Options: nosniff`. No row is `404`.
- `DELETE /avatar` removes the row and returns `204` even when there was no photo.

On `/api/auth/me` and on the login `user` object, add `username`, `bio`, and `has_avatar` from `readProfile`. Keep every field those responses already return.

In `publicUser` (`server/routes/register.js`), add `username: null`, `bio: null`, `has_avatar: false`. A brand-new account has no profile yet. Do not query the avatar table on the signup path.

**Verify**: the profile mocha command in the table exits 0. Cases in `server/routes/profile.test.js`:

- `PUT` of a 1×1 JPEG, then `GET`, returns those bytes and `content-type: image/jpeg`.
- `PUT` of `<html>` returns 400 and `GET` stays 404.
- `DELETE` then `GET` is 404.
- A request with no auth is 401. Mount `authenticateToken` in the test app the same way production does, or a tiny middleware that 401s when `req.user` is missing. Do not skip auth in the test app.

Also run `routes/user.test.js` and `routes/register.test.js` so preferences and signup still pass.
