## Why this matters

The Account page is where the streak, the word count, and the achievements sit next to each other. They do not measure the same things today, so a learner can have 50 words on the tile and still see “Master 50 vocabulary words” locked. Another badge says “7 days in a row” while the code counts any 7 days. A third badge asks for a perfect quiz, and no screen in the app gives a quiz.

## Current state

`server/services/badgeService.js` awards five badges:

```3:23:server/services/badgeService.js
const BADGE_CHECKS = {
  streak_7: (userId) => {
    const row = db.prepare('SELECT streak_days FROM user_stats WHERE user_id = ?').get(userId);
    return row && row.streak_days >= 7;
  },
  vocab_50: (userId) => {
    const row = db.prepare('SELECT COUNT(*) as count FROM user_vocab_progress WHERE user_id = ? AND reps > 0').get(userId);
    return row.count >= 50;
  },
  quiz_perfect: (userId) => {
    const row = db.prepare("SELECT 1 as found FROM quiz_sessions WHERE user_id = ? AND score = total_questions AND total_questions > 0 LIMIT 1").get(userId);
    return !!row;
  },
  playlist_first: (userId) => {
    const row = db.prepare('SELECT COUNT(*) as count FROM playlists WHERE user_id = ?').get(userId);
    return row.count >= 1;
  },
  daily_word_7: (userId) => {
    const row = db.prepare('SELECT COUNT(DISTINCT date) as count FROM daily_words WHERE user_id = ?').get(userId);
    return row.count >= 7;
  }
};
```

The seed in `server/db.js` (only when `badges` is empty) says `daily_word_7` is “Get your daily word 7 days in a row” and `vocab_50` is “Master 50 vocabulary words”. Production already has those rows, so an edit to the seed alone will not change them.

`GET /api/progress/stats` (`server/routes/progress.js`) returns `streak_days` from `computeDailyWordStreak` and `total_words` as `COUNT(*)` from `daily_words`. `today_goal_met` is true at 1 word today. `daily_goal` is hardcoded to 10. Android draws Today as `today_words/daily_goal`, so the tile can read `1/10` on a day that already counts for the streak.

`computeDailyWordStreak` (`server/services/dailyWordService.js`, around line 1214) walks distinct `daily_words.date` values backward from today, and still counts yesterday if today has no word yet. `user_stats.streak_days` is only rewritten when a new word is delivered. A stored 7 can therefore outlive the real streak, and a real 7-day run that later breaks never unlocks `streak_7` if the learner did not open stats while `user_stats` still said 7.

Receiving a word enrolls it with `reps` 0 (`server/services/reviewEnrollment.js`). `reps` becomes greater than 0 only after a review is saved. So the Words tile and `vocab_50` are different counts.

`GET /api/badges` (`server/routes/badges.js`) lists every badge, including locked ones, and does not award anything. Awarding happens inside `GET /api/progress/stats`. Android Settings loads stats, then badges. The web Account page does not list achievements. `BadgeGrid` is only referenced from `DashboardMatureCards`, which no page renders.

Do not change `server/routes/study.js`. Leave quiz tables in place.

## Steps

### Step 1: One progress snapshot

Add `progressSnapshot(userId)` to `server/services/badgeService.js` and use it for both awarding and the list. It reads:

- `words` = `COUNT(*)` from `daily_words` for that user. This is “words obtained”.
- `days` = `COUNT(DISTINCT date)` from `daily_words`.
- `reviewed` = `COUNT(*)` from `user_vocab_progress` where `reps > 0`.
- `playlists` = `COUNT(*)` from `playlists`.
- `best_streak` = the longest run of consecutive `YYYY-MM-DD` dates in `daily_words`. Sort the distinct dates, and start a new run when the next date is not exactly one UTC day after the previous. A single date has best streak 1. No rows means 0.
- `current_streak` is not calculated here. Callers that need the header number keep using `getDailyWordStats().streak_days`.

Rules:

| id | Unlocks when | progress | target |
|----|----------------|----------|--------|
| `streak_7` | `best_streak >= 7` | `best_streak` | 7 |
| `daily_word_7` | `days >= 7` | `days` | 7 |
| `vocab_50` | `words >= 50` | `words` | 50 |
| `review_10` | `reviewed >= 10` | `reviewed` | 10 |
| `playlist_first` | `playlists >= 1` | `min(playlists, 1)` | 1 |

Remove `quiz_perfect` from `BADGE_CHECKS`. Do not delete its row.

`checkAndUnlockBadges` still inserts into `user_badges` only for badges that pass, and still returns only the ones newly inserted. It must ignore a stored `user_stats.streak_days` of 7 when `best_streak` is below 7.

In `server/db.js`, after the badge seed, always run updates so existing databases change too:

- `daily_word_7` description becomes `Get a word on 7 different days`. Name stays `Daily Dedication`.
- `vocab_50` name becomes `50 Words`. Description becomes `Get 50 words`.
- `streak_7` description becomes `Reach a 7-day streak`. Name stays `7-Day Streak`.
- Insert `review_10` if that id is missing: name `10 Reviews`, description `Review 10 words`, icon `BookOpen`, category `vocabulary`, criteria `{"type":"words_reviewed","threshold":10}`.

`GET /api/badges` calls `checkAndUnlockBadges` first, then returns badges except `quiz_perfect`, each with `unlocked`, `progress`, and `target`. Order by category, then id.

`GET /api/progress/stats` adds `days_learned` and `words_reviewed` from the same snapshot. Do not change `streak_days`, `total_words`, `today_words`, `today_goal_met`, or `daily_goal`.

**Verify**: the badge mocha command exits 0, including these cases:

- Seven `daily_words` dates with a one-day gap between each unlock `daily_word_7` and do not unlock `streak_7`.
- Seven consecutive dates unlock both. The existing test in `routes/progress.test.js` that inserts 1–7 January 2026 and expects `daily_word_7` must still pass. `streak_7` may also be in that first response. Do not assert that it is absent.

- 10 progress rows with `reps > 0` and no `daily_words` unlock `review_10` and do not unlock `vocab_50`.
- `GET /api/badges` JSON has no `quiz_perfect`, and `daily_word_7` includes `progress` and `target`.

Update `server/services/badgeService.test.js`. The test that inserts only `user_stats.streak_days = 7` is no longer a passing case. Replace it with the consecutive-dates case.
