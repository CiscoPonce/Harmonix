<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Client route ID → Express/Spotify | Untrusted provider IDs select external resources. |
| User-scoped SQLite playlist row → detail DTO | Persisted normalized list metadata can authorize restricted detail only for its owning user and freshness window. |
| Spotify item payload → web/native UI | Nullable and malicious display data reaches renderers. |
| API external URL → browser/url_launcher | Provider-returned navigation leaves Harmonix. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-12-27 | Elevation of Privilege | Playlist detail ID | high | mitigate | Allowlist provider, encode/validate ID, use current user's token, and test cross-provider collisions. |
| T-12-28 | Spoofing | External deep link | high | mitigate | Accept only API-provided HTTPS open.spotify.com links in both clients. |
| T-12-29 | Tampering | Display data | medium | mitigate | Plain-text rendering, defensive nullable parsing, and no HTML interpretation. |
| T-12-30 | Information Disclosure | Restricted playlist | high | mitigate | Require prepared `(req.user.id, spotify_playlist_id)` lookup, approved expiry, complete user-scoped `/me/playlists` revalidation when stale, non-disclosing absent/cross-user responses, and disconnect deletion tests. |
| T-12-31 | Denial of Service | Item pagination | medium | mitigate | Bounded pages, provider timeout/rate wrapper, and explicit retry states. |
</threat_model>
