**Gathered:** 2026-07-21

<domain>
## Phase Boundary

Let a signed-in Harmonix learner **play Spotify tracks from an in-app Spotify playlist detail** on web (and Android where feasible), instead of only using **Open in Spotify**.

**In scope**

- Spotify **Web Playback SDK** (or current Spotify-supported playback API) for Premium users
- OAuth scope expansion required for playback (research official 2026 scopes; minimize)
- Backend-issued short-lived player credentials / token proxy pattern that never exposes refresh tokens to the browser
- Playlist detail play controls: play / pause / next-previous within the opened Spotify playlist (capped list already ≤20 rows)
- Clear Premium / unavailable / restricted / offline / rate-limit states
- Keep **Open in Spotify** as fallback when SDK cannot play
- Attribution and Design Guidelines compliance for Spotify branding
- Update `docs/SPOTIFY-INTEGRATION.md` and COVERAGE.md (OPT-OUT → INTEGRATE for playback)

**Out of scope**

- Replacing Deezer 30s preview path for Harmonix-native songs / Daily Word
- Background free-tier full-catalog streaming without Premium (Spotify product rules)
- Sending Spotify audio or track content to NVIDIA NIM / AI pipelines
- Editing Spotify playlist order from Harmonix
- Public Extended Quota (remains separate release gate)
- Apple Music / other providers

</domain>

<decisions>
## Implementation Decisions (locked for planning)

### Product
- **D-12.6-01:** In-app Spotify playback is an **opt-in Premium experience** on Spotify playlist detail; Harmonix content continues to use Deezer 30s previews.
- **D-12.6-02:** If playback is unavailable (non-Premium, SDK blocked, restricted playlist), show honest copy and keep **Open in Spotify**.
- **D-12.6-03:** Do not autoplay on detail open; user must press Play.
- **D-12.6-04:** Playing a Spotify track must not start Harmonix learning/AI extraction on that track in this phase.

### Security & tokens
- **D-12.6-05:** Refresh tokens stay server-side encrypted; browser/device only receive short-lived access material needed by the SDK, via Harmonix API.
- **D-12.6-06:** Re-consent / reconnect path when new scopes are required (Settings Reconnect).
- **D-12.6-07:** Never log access tokens, SDK device IDs beyond safe ops ids, or full Spotify payloads.

### Platforms
- **D-12.6-08:** Web first (Next.js). Android Flutter follows if Web Playback / App Remote pattern can share backend token rules without duplicating secrets on device.
- **D-12.6-09:** Preserve Phase 10 light/green UI language; player chrome stays minimal (one composition, not a second app shell).

### Compliance
- **D-12.6-10:** Follow Spotify Developer Terms + Design Guidelines for playback UI and attribution.
- **D-12.6-11:** Copyright rule in CLAUDE.md still applies to Harmonix-owned preview path; Spotify playback is Spotify-licensed via the user’s Premium account, not Harmonix hosting audio files.

</decisions>
