<objective>
Enable Harmonix to produce the phonetic sound of the "Word of the Day". This is achieved by running Pocket-TTS as a local HTTP daemon on port 3002, modifying its audio output to include 1.0 second of silence padding at the start and end, caching generated audio bytes in a new SQLite table, securing the pronunciation endpoint behind the project's standard auth middleware, and integrating a manual speaker button in the frontend.
</objective>

<tasks>
<task type="auto">
  <name>Task 1: Add SQLite Cache Schema</name>
  <files>server/db.js</files>
  <action>
  Extend db.js to create the `word_pronunciation_cache` table if it does not exist:
  ```sql
  CREATE TABLE IF NOT EXISTS word_pronunciation_cache (
    word TEXT NOT NULL,
    language_code TEXT NOT NULL,
    audio_data BLOB NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (word, language_code)
  );
  ```
  Implement helper functions `getCachedAudio(word, langCode)` and `saveCachedAudio(word, langCode, audioBlob)` using standard sqlite prepared statements.
  </action>
  <done>Database schema and helper functions for pronunciation cache implemented.</done>
</task>

<task type="auto">
  <name>Task 2: Implement Audio Silence Padding in Pocket-TTS</name>
  <files>pocket-tts/pocket_tts/data/audio.py</files>
  <action>
  Modify `stream_audio_chunks` or `StreamingWAVWriter` to pad the audio output with silence:
  1. Write 1.0 second of silence at the beginning: `writer.write_pcm_data(torch.zeros(sample_rate))`
  2. Increase the trailing silence in `StreamingWAVWriter.finalize()` to 1.0 second (from the default 200ms) to ensure proper playback padding.
  This prevents words from being cut off or spoken too fast due to network streaming or browser playback initiation.
  </action>
  <done>Pocket-TTS audio stream modified with 1.0s silence padding at the beginning and end.</done>
</task>

<task type="auto">
  <name>Task 3: Backend API Endpoint & Auth Routing</name>
  <files>server/routes/dailyWord.js</files>
  <action>
  Implement `GET /api/daily-word/pronounce?word=...&lang=...` inside the dailyWord router:
  1. This route is automatically protected by the Express app's `authenticateToken` middleware.
  2. Validate query params: ensure `word` is a non-empty string and `lang` matches one of the supported language codes.
  3. Query `word_pronunciation_cache`. If found, send the binary data directly as `audio/wav`.
  4. If not found, fetch from the local Pocket-TTS endpoint `http://127.0.0.1:3002/tts` using a multipart request with standard parameters:
     - `text`: the target word string
     - `voice_url`: the designated default voice for the target language (e.g. `lola` for es, `estelle` for fr, etc.)
  5. Cache the fetched audio bytes in `word_pronunciation_cache`, set the response `Content-Type: audio/wav`, and stream/send it to the client.
  </action>
  <done>Secure API route for pronunciation caching and streaming added to dailyWord routes.</done>
</task>

  2. Under the main startup sequence, start Pocket-TTS on port `3002` (one above backend 3001):
     ```bash
     echo "Starting Pocket-TTS on port 3002..."
     cd "$PROJECT_ROOT/pocket-tts"
     nohup uv run pocket-tts serve --host 127.0.0.1 --port 3002 > "$LOG_DIR/tts.log" 2>&1 &
     echo $! > "$LOG_DIR/tts.pid"
     wait_for_port 3002 "Pocket-TTS"
     ```
