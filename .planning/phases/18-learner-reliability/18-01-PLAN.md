# Plan 18-01: Queue, search, and streak correctness

## Objective

Next, search, and the streak counter agree with what the learner already has.

## Work

1. **Native language purge.** In `server/routes/user.js`, when `native_language` changes, call the same path as target language: `abortRefill`, `bumpPreferenceEpoch`, `wordQueue.purgeAll`. Add a route test next to the existing target-language purge test in `server/routes/user.test.js`.
2. **Discard, don’t consume, on duplicates.** In `consumeNextDailyWord` (`server/services/dailyWordService.js`), duplicate word and duplicate song checks must run before `consumeById`, and the skip must `discard` the row. `pickNextQueueItem` should also skip lemmas already in delivered history. Extend the existing “skips duplicate queued words” test so the skipped row is gone and a later unused card still serves.
3. **Search avoids the queue.** `generateDailyWordFromTrack` must pass words from `getUserDiscoveryHistory` (delivered plus ready queue), not only `getDeliveredDiscoveryHistory`. Add a service test: enqueue `amor`, then from-track on a lyric that also contains `amor` must pick a different lemma or reject.
4. **Streak calendar.** `todayDate()` and `computeDailyWordStreak` must use one calendar. Prefer UTC for both, and step the cursor in UTC (not `setDate` on a local `Date` then `toISOString`). Add tests for a gap day, an empty history, and a date that is “today” in UTC but “yesterday” in a negative offset.

## Out of scope

- Song reuse
- UI copy for exhaustion (18-04)
