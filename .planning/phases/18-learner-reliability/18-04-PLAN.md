# Plan 18-04: Exhausted catalog and thin styles

## Objective

When Next cannot find an unused song, the learner gets a next step. Styles with no songs in that language are not offered as if they work.

## Work

1. **Exhaustion actions.** Keep generation strict (no `allowSongReuse` on Next). When the reason is `song_already_used` (and the widened pass also fails), web `DailyWordCard` and Flutter learn screen show:
   - the existing honest sentence
   - a control that opens Settings music style
   - a control that focuses song search
   Copy lives in the existing i18n dictionaries (`client/src/lib/i18n.dictionary.ts`, `mobile/lib/utils/i18n.dart`), not a new English-only string on Flutter.
2. **Thin styles.** Settings on web and Flutter must not offer a genre that has an empty verified and curated pool for the current target language (example: English + reggaeton in `server/services/aiService.js`). Prefer hiding the chip. Filling `VERIFIED_SONGS` is allowed for a cell you choose to keep, using the existing scan notes in `docs/LANGUAGE-RELIABILITY.md`. Do not stamp the wrong genre onto a song.

## Out of scope

- Growing every language×genre cell in one pass
- Re-enabling same-song fallback

## Done when

- A client test (web unit or Flutter widget) shows the exhaustion actions for `song_already_used`.
- A settings test shows reggaeton hidden for English (or whichever empty cell you lock) and still shown for a language that has that catalog.
