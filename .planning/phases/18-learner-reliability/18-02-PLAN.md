# Plan 18-02: Rate limits, password length, proxy bump

## Objective

Stop one account from hammering AI routes, and stop Settings from weakening a password below the registration bar.

## Work

1. **Daily-word limiter.** Add a per-user limiter in `server/middleware/security.js` and mount it on `POST /api/daily-word/new`, `POST /next`, and `POST /from-track` in `server/routes/dailyWord.js` (or the router mount in `server/index.js`). Keep test mode loose, matching `authLimiter`. A sensible production window is about 20 requests per minute per user. Do not set song reuse as the cost control.
2. **Password minimum.** `server/routes/password.js` must reject `newPassword.length < PASSWORD_MIN` from `server/middleware/security.js` (8). Mirror the check in `client/src/app/settings/page.tsx` and the Flutter change-password field if one exists. Grandfather existing hashes: only the new password is checked.
3. **Proxy dependency.** In `server/`, run `npm audit` and bump `http-proxy-middleware` off `4.1.0` to a release that clears the high advisory (expected `>=4.1.1`). Re-run server tests. If the advisory does not apply to this install, record that in the plan notes and stop the bump.

## Done when

- A test asserts change-password rejects a 6-character password and accepts 8.
- A test asserts the daily-word limiter is mounted (or returns 429 after the cap in test with a lowered limit).
- `cd server && npm test` exits 0.
- `server/package-lock.json` no longer resolves `http-proxy-middleware` to `4.1.0`, unless the audit note says the advisory is absent.
